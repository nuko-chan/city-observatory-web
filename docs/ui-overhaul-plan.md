# UI オーバーホール実装計画

## 背景

DESIGN.md のカラートークン・タイポグラフィ・shadow-as-border は適用済み。
しかしレイアウト構造自体が「同じサイズのカードを縦に積むだけ」で、情報の階層がない。
本計画では、モダンな天気アプリに共通する **ヒーロー → コンパクトグリッド → 時系列** の3層構造に再構成する。

## 現状の問題

| 問題                   | 詳細                                                           |
| ---------------------- | -------------------------------------------------------------- |
| ヒーローが弱い         | 気温・天気状態が他のカードと同じ視覚的重み                     |
| 情報密度が低い         | UV・快適度・風速が各々フルワイドのカード。縦スクロール量が多い |
| 都市選択が分離         | 別コンテナに隔離されていてヘッダーと断絶                       |
| チャートが冗長         | 気温チャートとPM2.5チャートが同サイズで縦に並ぶだけ            |
| マップの存在意義が薄い | 右カラムにただ配置されているだけ                               |

## ゴール

- 「今の天気」を1秒以内に認知できるヒーロー表示
- 縦スクロール量を現状の約40%削減
- 情報の重要度に応じた視覚的階層
- DESIGN.md のデザインシステムを活かしたレイアウト

## 実装フェーズ

### Phase A: ヒーローセクション

**変更対象**: `app/page.tsx`, `features/weather/ui/weather-card.tsx`

**概要**: WeatherCard を解体し、ヒーロー専用のレイアウトに再構成。都市選択をヒーロー内に統合。

**具体的な変更**:

1. **気温を巨大表示** — `text-[7rem]` (112px) + Geist Mono + tnum。DESIGN.md の Display Hero（48px）を超えるが、天気アプリのメイン気温はこのスケールが標準
2. **天気アイコンを大型化** — 現在の `h-5 w-5` → `h-16 w-16` 以上。気温の横に配置
3. **サブ指標を横並び** — 湿度・風速・降水確率をヒーロー下部にインラインで `·` 区切り表示
4. **都市選択をヒーロー上部に移動** — 別コンテナ（現在の `.rounded-2xl` wrapper）を廃止し、ヘッダー行の右側にピルを直接配置
5. **コンディションバッジを大型化** — 天気アイコンの横に「快晴」等のラベルを大きめに

**WeatherCard の分割**:

- 現在の WeatherCard は「ラベル + 気温 + 体感 + 2×2グリッド」の1コンポーネント
- ヒーロー用の props はそのまま page.tsx で直接使い、WeatherCard は廃止せず compare ページ用に残す
- あるいは WeatherCard に `variant: "hero" | "compact"` を追加

**削除されるもの**:

- 都市選択の独立コンテナ（`.rounded-2xl bg-background/40 p-5`）
- WeatherCard を囲む GlassCard（ヒーローはカード枠なしで背景に直接描画）

### Phase B: メトリクスグリッド

**変更対象**: `app/page.tsx`, `features/weather/ui/uv-card.tsx`, `features/weather/ui/wind-card.tsx`, `features/derived-metrics/ui/comfort-summary-card.tsx`

**概要**: UV・快適度・風速を 3 列（モバイルでは 2×2）のコンパクトグリッドに。

**具体的な変更**:

1. **グリッドコンテナ** — `grid grid-cols-2 lg:grid-cols-3 gap-4` で各カードを配置
2. **カードの高さ統一** — 全カードを同じ高さに揃える。`min-h-[140px]` 程度
3. **UVCard のコンパクト化** — 大きな数値 + プログレスバーのみ。`/ 11+` テキストは削除可能
4. **ComfortSummaryCard** — スコア数値 + リスクレベルのみ。PM2.5 はバッジのまま残す
5. **WindCard のコンパクト化** — コンパスを小型化（`h-12 w-12`）、北/南ラベルは削除

**新規追加**:

- PM2.5 を独立した小カード（4番目のグリッドセル）にするオプション。モバイルで 2×2 が綺麗になる

### Phase C: SunPath バンド + チャートタブ化

**変更対象**: `app/page.tsx`, `features/weather/ui/sun-path-card.tsx`, `features/weather/ui/weather-chart-client.tsx`, `features/air-quality/ui/aq-chart-client.tsx`

**概要**: SunPath を細長いバンドに、チャート2つをタブ切り替えに統合。

**具体的な変更**:

1. **SunPath バンド** — 独立カードではなく、メトリクスグリッドの下にフルワイドの細いバンド（`h-16` 程度）として配置。SVG アークを横長に引き伸ばし、日の出/日の入り時刻を両端に
2. **チャートタブ** — 気温チャートと PM2.5 チャートを1つの GlassCard 内にタブ切り替えで格納。`useState` でアクティブタブを管理
3. **チャート + マップを横並び** — `lg:grid-cols-2` でチャート（左）とマップ（右）を同じ行に

**削除されるもの**:

- SunPathCard の独立 GlassCard ラッパー
- PM2.5 チャートの独立 GlassCard ラッパー

### Phase D: Compare ページ同期 + ポリッシュ

**変更対象**: `app/compare/page.tsx`

**概要**: Home で確立した新レイアウトを Compare ページにも適用。

**具体的な変更**:

1. Compare ページの左右セクションにも同じヒーロー + グリッド構造を適用（ただしヒーローは小さめ）
2. カスケードアニメーションのタイミング調整
3. 全ページ通しての余白・タイポグラフィの最終調整

## リスクと判断

| リスク                       | 対策                                                                                    |
| ---------------------------- | --------------------------------------------------------------------------------------- |
| WeatherCard の互換性         | compare ページでも使うため、variant prop で分岐するか、ヒーロー部分は page.tsx に直書き |
| チャートタブの状態管理       | 単純な `useState` で十分。URL state（nuqs）は不要                                       |
| SunPath の横長化で視認性低下 | バンド高さを最低 `h-16` 確保、進行率の数値表示は残す                                    |
| モバイルでのグリッド崩れ     | `grid-cols-2` を基本とし、風速カードが狭い場合はコンパスを省略                          |

## 判断が必要な点

1. **WeatherCard を廃止 or variant 追加？** — ヒーロー用に page.tsx 直書きが最もシンプル。compare 用に既存 WeatherCard を残す
2. **PM2.5 を独立小カード化するか？** — グリッドが 4 セル（2×2）になりモバイルで綺麗。ただし ComfortSummaryCard 内の PM2.5 バッジと重複する
3. **マップの配置** — チャートと横並び vs 画面下部にフルワイド。横並びがデスクトップでは見栄えが良い
